# Economy Specification v0.1

상태: GDD의 확정 원칙을 구현 가능한 규칙으로 구체화한 제안 초안. 아래 새 공식, 수치, 세부 동작은 사용자 확정값이 아니다. 이번 검산에 사용한 값과 후속 구현 제안은 구분한다.

## 1. 단위와 기본 규칙

- 모든 수요·급여·시설비 표기의 시간은 게임 내 시간이다.
- 검증용 시간 배율: 현실 1초 = 게임 1분. 현실 1분 = 게임 1시간.
- 경제 처리 간격: 게임 1분. 화면의 프레임 수와 독립적으로 처리한다.
- 초기 자금 600G, 테이블 1개, 일반 딜러 1명, 인지도 0, 만족도 80.
- 테이블당 8석. 한 딜러는 한 테이블을 담당한다. 첫 버전에는 휴식·교대·피로가 없다.
- 일반 세션은 고정 120게임분, 완료 매출 200G. 첫 버전에서 평균이라는 표현은 동일한 고정 이용 시간을 가리킨다.
- 세션 완료 즉시 매출 확정 및 좌석 해제. 퇴장 연출 완료를 기다리지 않는다.
- 착석 중 손님은 중도 퇴장하지 않는다. 저장·앱 종료는 세션 취소가 아니다.
- 실제 포커의 최소 참가자 수나 핸드 진행을 모사하지 않는다. 한 명이라도 착석하면 독립적인 이용 세션을 시작한다.

금액은 표시용 반올림과 내부 계산을 구분한다. 제작용 엔진은 정수 기반의 충분히 작은 화폐 단위 또는 동등한 정밀 계산을 사용해 매분 비용 차감의 반올림 누적을 막는다. 이번 검산 도구의 부동소수 계산을 그대로 제품에 복사하지 않는다.

## 2. 최소 상태 항목

| 상태 | 주요 항목 |
|---|---|
| 매장 | 단계, 현금, 인지도, 만족도, 테마, 시설 레벨 |
| 시간 | 게임 경과 분, 마지막 반영 현실 시각, 방문 수요 소수 누적값 |
| 테이블 | 고유 ID, 설치 지점 ID, 층, 상태, 담당 딜러 ID |

| 세션 | 고유 ID, 테이블 ID, 시작 분, 완료 예정 분, 확정 예정 금액, 정산 여부 |
| 대기 | 도착 순서, 도착 분 |

설치 테이블 수와 근무 딜러 수의 최솟값은 모든 테이블이 사용 가능할 때의 단순식이다. 실제 엔진은 대회 예약·배치 대기·정리 중인 테이블을 제외해 각 테이블의 상태에서 운영 좌석을 계산한다.

## 3. 방문 수요

```text
A = 인지도, 0~100
S = 만족도, 40~95
기본 방문 수요 B = 1단계 3.5, 2단계 6
시간당 방문 수요 D = B × (1 + A / 10) × (0.75 + 0.5 × S / 100)
```

초기 D는 4.025명/게임시간이다. 인지도·만족도에 상한을 두어 무한 증가를 막는다. 2단계는 상권 확장을 추상화해 기본 수요를 6으로 높인다. 인지도 100·만족도 80이면 75.9명/시간으로 일반 테이블 18개의 처리 능력 72명/시간을 초과할 수 있다. 단계 변경 직후 유입 급증과 18개까지의 성장 곡선은 후속 검증 대상이다.

매분 `방문 소수 누적값 += D / 60`. 정수 부분만 신규 방문객으로 만들고 소수 부분은 보존한다. 첫 버전은 무작위 도착을 사용하지 않는다. 반복 계산·저장 복원에서도 같은 결과를 재현한다.

인지도 증가:

- 일반 영업의 완료 세션 1건당 +0.02. 다음 분 수요부터 적용한다.
- 소규모 대회 정상 완료 +12, 중규모 +18. 중복 정산 금지.
- 제안하는 초기 수요 확보 수단: 지역 홍보 400G, 인지도 +5, 재사용 간격 6게임시간. 인지도 40 미만에서만 구매 가능하고 구매 직후 40을 조금 초과할 수 있다.

지역 홍보는 첫 대회 이전의 수요 병목을 해결하기 위해 이번 초안에서 추가했다. 사용자가 확정한 기존 기능으로 취급하지 않는다. 이 기능을 제외하려면 초반 인지도 확보 경로와 성장 수치를 다시 검증한다.

## 4. 착석·대기·처리 능력

신규 방문보다 기존 대기 손님을 먼저 착석시킨다. 일반 영업 가능 테이블의 빈 좌석에 고유 ID 오름차순으로 배정한다. 1단계 대기 정원 8명, 2단계 16명. 기다린 시간이 30게임분에 도달하면 착석 전에 이탈한다. 대기열이 가득 찬 신규 방문객도 이탈한다.

빈 좌석이 있더라도 대회 예약 테이블에는 일반 손님을 받지 않는다. 대기 이탈과 착석 후 중도 퇴장을 구분한다.

```text
테이블별 세션 시간 = ceil(120 / 담당 딜러 속도 배율) 게임분
시간당 이론 처리 능력 = Σ(운영 테이블의 8석 × 60 / 세션 시간)
```

일반 딜러 테이블은 시간당 최대 4명, 숙련 딜러 테이블은 세션 100분으로 시간당 최대 4.8명이다. 이론 처리 능력은 정상 상태의 상한이며, 초기 빈 매장·대기 이탈·진행 중 대회 때문에 실제 완료 이용객과 다를 수 있다.

손님이 적을 때 숙련 딜러는 완료 시점을 앞당길 수 있지만 장기적으로 수요보다 많은 이용객을 만들어내지 못한다.

## 5. 직원과 시설

| 직원 | 획득 초안 | 시간당 급여 | 효과 |
|---|---|---:|---|
| 일반 딜러 | 시작 1명, 추가 고용 400G | 80G | 담당 테이블 속도 1.0 |
| 숙련 딜러 | 테이블 3개 달성 시 1명 확정 지급 | 110G | 담당 테이블 속도 1.2 |
| 대회 전문 딜러 | 첫 소규모 대회 완료 시 1명 확정 지급 | 100G | 일반 속도 1.0, 대회 운영 속도 1.25 |
| 서비스 직원 | 고용 600G | 60G | 서비스 수용 기준 +16명 |

확정 지급은 이번 검증 버전에서 능력 비교를 위한 제안이다. 같은 해금 보상을 두 번 받지 않는다. 특별 직원은 대기 상태로 지급하며 자동으로 기존 직원을 교체하지 않는다. 검산의 성장 경로에는 두 특별 직원의 효과를 넣지 않았다.

근무·정리 중 직원에게 급여를 지급한다. 대기 중 직원은 급여가 없다. 첫 버전에서는 해고·매각을 제공하지 않고 대기 전환을 제공한다. 기본 딜러와 설치한 테이블을 영구히 잃는 경로를 만들지 않는다.

딜러 교체·테이블 휴업 요청은 신규 착석을 막고 기존 세션이 완료된 후 반영한다. 진행 중 세션은 시작 시 확정한 시간과 금액을 유지한다. 딜러 한 명이 동시에 여러 테이블에 능력을 제공할 수 없다.

일반 영업·정리·대회 예약·대회 진행 테이블은 개당 30G/게임시간 시설비를 낸다. 빈 상태의 미운영 테이블은 시설비가 없다. 기본 매장 운영비는 40G/게임시간이다. 서비스 직원은 배치 상태에서 급여를 낸다.

편의시설은 0~2레벨, 1레벨 비용 1,000G, 2레벨 추가 비용 2,500G. 레벨당 목표 만족도 +3. 테마 외형과 능력은 분리한다.

## 6. 서비스 품질과 만족도

```text
서비스 수용 기준 = 8 + 16 × 근무 서비스 직원 수
O = 현재 일반 영업 중 착석 인원
서비스 품질 Q = min(100, 100 × 서비스 수용 기준 / max(8, O))
이탈률 L = min(1, 최근 6게임시간 대기 이탈 수 / max(1, 같은 기간 신규 방문 수))
목표 만족도 T = clamp(80 + 3 × 편의시설 레벨 + 0.15 × (Q - 100) - 10 × L, 40, 95)
S_next = S + (T - S) × (1 - exp(-Δ게임시간 / 6))
```

만족도는 매분 갱신하되 약 6게임시간에 걸쳐 서서히 반응한다. 짧은 혼잡이 즉시 수요 붕괴를 만들지 않도록 한다. 손님 도착 전 수요 계산에는 그 분의 갱신 전 만족도를 사용한다.

첫 버전의 대회 참가자는 일반 서비스 수용 계산에서 제외한다. 대회 운영비에 행사 서비스 비용을 포함한 것으로 추상화한다. 향후 별도 행사 서비스 요구량을 추가할 수 있다.

## 7. 매출·순이익·현금 흐름

- 일반 영업 매출 = 정상 완료 세션 수 × 200G.
- 영업 순이익 = 일반 영업 매출 + 완료 대회 순이익 − 해당 기간 급여·테이블비·매장비·홍보비.
- 대회 순이익 = 참가비 − 상금 − 참가자별 운영비 − 고정 개최비. 급여와 테이블비는 전역 비용에서 차감하므로 여기에 다시 넣지 않는다.
- 현금 잔액 변화 = 모든 실제 입출금. 테이블 구매·고용·시설 구매·리모델링 비용도 반영한다.

시설 구매 등 일회성 투자와 반복 영업 비용은 화면에서 구분한다. 대회 준비비는 예약 때 현금에서 잠그고, 완료 때 비용으로 인식한다. 엔진은 잠긴 금액을 구매 가능 현금으로 표시하지 않는다. 이번 검산은 준비비를 예약 즉시 비용 처리하므로 짧은 기간의 보고 화면과는 차이가 있다.

## 8. 대회

‘데일리’는 **게임 내 24시간으로 구분되는 하루당 1회 예약**으로 제안한다. 현실 날짜·자정·접속 보상을 사용하지 않는다. 게임일 번호는 `floor(경과 게임분 / 1440)`이다. 두 대회를 동시에 예약할 수 없고, 예약 시 그 게임일의 개최권을 사용한다.

| 항목 | 소규모 | 중규모 |
|---|---:|---:|
| 예약 테이블·딜러 | 각 2 | 각 4 |
| 최소/최대 참가자 | 8 / 16 | 16 / 32 |
| 예상 참가자 | min(16, floor(D × 2)) | min(32, floor(D × 3)) |
| 기본 진행 시간 | 240게임분 | 360게임분 |
| 1인 참가비 | 180G | 240G |
| 1인 상금 예산 | 60G | 100G |
| 1인 운영비 | 20G | 30G |
| 고정 개최비 | 600G | 1,800G |
| 인지도 보상 | +12 | +18 |

참가자 수는 예약 시 수요로 확정한다. 확률적인 모집 실패나 노쇼는 첫 버전에 없다. 이 모집 공식과 중규모 수치는 검증용 가정이며 중규모는 이번 계산 실험에서 검증하지 않았다.

예약 전: 해금, 최소 참가자, 테이블·딜러 확보, 다른 대회·리모델링 부재, 준비비 지급 후 운영 예비금 확보를 검사한다. 예약할 수 없는 이유를 표시한다.

진행 순서:

1. 참가자·비용·담당 테이블·직원을 고정하고 준비비를 잠근다.
2. 예약 테이블을 정리 상태로 바꿔 신규 일반 손님을 받지 않는다.
3. 기존 이용객의 정상 세션이 모두 끝나면 대회가 시작된다.
4. 지정된 딜러를 대회 종료까지 고정한다. 일반 영업에 중복 배치할 수 없다.
5. 대회 전문 딜러가 1명 이상 있으면 전체 진행 시간은 `ceil(기본 시간 / 1.25)`이다. 여러 명의 동일 효과는 중첩하지 않는다.
6. 종료 시 참가비·비용·인지도·개최 실적을 한 번만 정산하고 일반 영업으로 복귀한다.

첫 버전에서는 예약 후 취소와 대회 도중 실패를 제공하지 않는다. 성패 확률 대신 참가 규모와 일반 영업 기회비용을 판단하는 데 집중한다. 같은 게임일에는 규모와 관계없이 개최권을 공유한다.

대회 경제 효과는 동일 기간에 대회를 열지 않았을 때와 비교한다. 참가비 전체 또는 대회 자체 흑자를 매장 전체의 추가 이익이라고 표현하지 않는다.

## 9. 투자 예상치

현재 상태를 복제해 ‘투자 안 함’과 ‘지금 투자함’을 같은 엔진으로 각각 24게임시간 진행한다. 양쪽 모두 이후 추가 클릭은 없다고 가정한다. 자동 수요·만족도 변화와 예약된 대회는 정상 진행한다. 원본 상태를 수정하지 않는다.

표시할 항목:

- 즉시 바뀌는 운영 테이블·이론 처리 능력.
- 현재 방문 수요와 예상 기간.
- 예상 추가 영업 매출, 추가 반복 비용, 추가 영업 순이익.
- 즉시 지급하는 투자 비용과 투자 후 현금.
- 직원 교체·대회 준비로 효과 발생이 지연될 경우 그 이유.

추가 영업 순이익과 일회성 투자 비용을 혼동하지 않는다. 회수 시간은 추가 순이익이 양수이고 가정이 유효할 때만 참고치로 표시한다.

‘수요 8명, 처리 능력 12→16명, 추가 매출 0G’는 정상 상태의 설명 예시다. 실제 24시간 예측에서는 진행 중 세션과 인지도 변화 때문에 값이 달라질 수 있다. 0G를 화면에 고정하지 않는다.

## 10. 매분 처리 순서

1. 직전 경계에서 승인한 플레이어 명령을 순서대로 반영한다.
2. 게임 시각을 1분 진행한다.
3. 이미 비어 있는 예약 테이블의 대회 시작을 판정하고, 종료 시각에 도달한 대회를 정산한다.
4. 완료 시각에 도달한 일반 세션의 매출을 정산하고 좌석을 비운다.
5. 갱신 전 만족도 및 현재 인지도로 수요를 계산하고 신규 방문 수를 누적한다.
6. 대기 만료를 처리하고 기존 대기 손님, 신규 방문객 순으로 착석시킨다. 잔여 방문객은 대기 또는 이탈한다.
7. 서비스 품질·최근 이탈률·만족도를 갱신하고 일반 세션의 인지도 보상을 반영한다.
8. 급여·시설비·운영비를 해당 1분만큼 차감한다. 필요 시 긴급 운영 규칙을 적용한다.
9. 해금·직원 배치 전환·리모델링 준비 완료를 판정하고 거래와 상태를 저장 대상으로 만든다.

3번의 시작 판정은 4번보다 앞이므로 마지막 일반 세션이 막 끝난 경우 대회 준비 완료를 다음 분에 확인한다. 순서 변경 시 같은 조건의 재현 결과도 바뀌므로 버전 변경으로 기록한다.

## 11. 자금 부족 시 복구 — 추가 제안, 미검증

투자 실수로 영구히 진행이 막히지 않도록 첫 버전에는 자동 ‘긴급 축소 운영’을 제안한다.

- 그 분의 매출 반영 후 필수 비용을 낼 수 없으면 발동한다.
- 신규 지출·대회 예약을 잠그고, 테이블 1개와 기본 딜러 1명만 남기는 배치를 예약한다.
- 기존 세션과 진행 중 대회는 정상 완료한다. 남는 직원·테이블은 순차적으로 대기로 바뀐다.
- 현금으로 낼 수 없는 필수 운영비만 임시 지원금으로 충당한다. 지원금은 매출·실적에 포함하지 않는다.
- 기본 1테이블 상태에서 4게임시간 운영비 600G를 확보하면 지원을 종료한다. 다른 직원은 자동 복귀하지 않는다.
- 지원 중 구매·리모델링은 불가하다. 이 상태는 예상치 화면에도 표시한다.

이 규칙은 초보자 복구 장치에 관한 신규 제안이다. 일반 플레이 수익으로 가장하지 않는다. 실제 구현 전에 반복 악용, 종료 가능성, 대회·리모델링과의 충돌을 검증해야 한다. 이번 계산 실험은 이 지원을 사용하거나 검증하지 않았다.

## 12. 저장·백그라운드·오프라인 — 구현 제안, 미검증

동일한 반영 대상 게임 시간은 화면의 표시 여부와 무관하게 같은 엔진으로 처리한다. 숨겨진 탭에서도 화면 프레임으로 시간을 세지 않는다. 경제 정산 완료와 출력 애니메이션을 분리한다.

첫 버전의 오프라인 상한 초안은 현실 4시간이다. 경과 시간 중 상한까지만 환산하고 나머지는 보상하지 않는다. 적용 후 기준 현실 시각을 현재로 갱신하여 재접속 때 초과 시간을 반복 수령하지 못하게 한다. 시계가 뒤로 이동하면 음수 경과 시간은 0으로 취급하고 기준 시각을 뒤로 되돌리지 않는다. 로컬 시계 조작의 완전한 방지는 온라인 구조에서 별도로 결정한다.

진행 중 세션과 예약 대회는 오프라인 계산에서 완료할 수 있다. 구매·고용·새 대회 개최는 자동으로 수행하지 않는다. 정상 영업 중 시간 청크 분할 결과와, 저장 복원 후 결과를 비교해야 한다. 이번 검산은 전자만 확인했다.

세션·대회·해금·리모델링에 안정적인 ID와 정산 상태를 둔다. 중복 클릭·재실행·저장 복구로 비용이 두 번 차감되거나 보상이 두 번 지급되어서는 안 된다.
