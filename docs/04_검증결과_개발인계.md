# 경제 검산 결과와 개발 인계

작성일: 2026-09-19. 대상: Economy/Progression v0.1의 일부 공식과 초기 수치.

## 1. 실제로 수행한 계산

별도의 간단한 경제 계산 도구로 게임 내 1분 단위의 방문·대기·테이블별 세션·일반 급여·시설비·만족도·소규모 대회 정리를 계산했다. 게임 화면과 제품용 엔진은 아직 만들지 않았다.

| 실험 | 조건 | 관측 결과 |
|---|---|---|
| 낮은 수요에서 딜러 추가 | 고정 수요 8명/시간, 5테이블, 딜러 3명 대 4명, 48게임시간 | 추가 매출 0G, 추가 비용 5,280G |
| 높은 수요에서 딜러 추가 | 고정 수요 20명/시간, 나머지 동일 | 완료 이용객 552명 → 736명, 추가 순이익 31,520G |
| 숙련 딜러 효과 | 1테이블, 고정 수요 20명/시간, 48게임시간, 속도 1.0 대 1.2 | 완료 이용객 184명 → 224명 |
| 서비스 직원 효과 | 5테이블·5딜러, 고정 수요 20명/시간, 48게임시간 | 서비스 직원 0명 만족도 68.00, 1명 74.00 |
| 시간 분할 일관성 | 동일 초기 상태, 1,440분 처리 대 60분씩 24회 처리 | 비교한 전체 상태 동일 |
| 초기 영업의 자금 유지 | 시작 자금 600G, 추가 투자 없이 48게임시간 | 최소 잔액 265G, 음수 잔액 없음 |

첫 두 실험은 수요와 인지도 변화를 고정해 처리 능력의 효과만 분리했다. 실제 매장의 24시간 투자 예측 수치로 그대로 사용하면 안 된다. 숙련 딜러 실험은 처리량만 검증했으며 추가 급여까지 포함한 경제성 비교가 아니다. 서비스 실험은 만족도 변화만 확인했으며 직원 고용이 모든 상황에서 이익이라는 결론이 아니다.

시간 분할 실험은 저장 직렬화·현실 시계·오프라인 상한 검증이 아니다. 동일 계산을 여러 묶음으로 실행했을 때 결과가 같다는 뜻이다.

## 2. 자동 투자 경로의 참고 결과

매 게임시간마다 정해진 정책으로 구매·고용·홍보·대회를 선택하는 가상 플레이어를 사용했다. 정책은 구매 후 약 4시간 운영비를 남기고, 수요가 현재 능력의 85%를 넘으면 추가 딜러를 검토한다. 테이블은 돈이 충분하면 구매하며, 해금 조건을 향한 투자를 포함한다. 최적 전략이나 사람의 행동을 모사한 것은 아니다.

| 사건 | 게임 경과 시간 | 제안 배율로 환산한 현실 시간 |
|---|---:|---:|
| 두 번째 테이블 구매 | 5시간 | 5분 |
| 세 번째 테이블 구매 | 10시간 | 10분 |
| 첫 소규모 대회 예약 | 14시간 | 14분 |
| 첫 대회 완료 | 약 19.97시간 | 약 19분 58초 |
| 두 번째 대회 예약 | 25시간 | 25분 |
| 여섯 번째 테이블 구매 | 30시간 | 30분 |
| 두 번째 대회 완료 | 약 30.95시간 | 약 30분 57초 |
| 리모델링 비용 지급 및 단계 변경 | 35시간 | 35분 |
| 일곱 번째 테이블 구매 | 39시간 | 39분 |
| 일곱 번째 테이블 영업 확인 | 41시간 | 41분 |

전체 경로에서 최소 잔액은 265G였다. 리모델링 직전 인지도는 55.4, 변경 직후 현금은 5,660G였다. 7번째 테이블 영업 확인 시 일반 딜러 7명과 서비스 직원 1명을 사용했다. 특별 직원은 사용하지 않았다.

**이 시간표는 실제 플레이 시간의 보장이 아니다.** 대회의 테이블 정리는 계산했지만 리모델링 정리 시간과 자산 전환 거래는 구현하지 않았다. 특별 직원 지급·편성, 중규모 대회, 저장 복원, 긴급 운영도 구현하지 않았다. 따라서 ‘35분에 완성된 게임에서 리모델링된다’고 해석하면 안 된다.

## 3. 현재 결과에서 발견한 조정 과제

1. 초기 세션이 2게임시간이므로 첫 매출까지 약 2분 15초가 필요하다. 첫 테이블 구매도 약 5분이다. 초반 체감이 느릴 수 있으므로 첫 손님 연출·튜토리얼 세션·초기 자금 또는 시간 배율을 검토한다. 보상 예외를 추가하면 명시적으로 규칙화한다.
2. 인지도와 현금 외에 대회 완료 횟수가 성장 속도를 제한한다. 이번 초안은 현실 일일 제한을 피하고 게임일별 개최권을 사용했다. 2회 조건이 선택을 유도하는지 단순 대기만 만드는지 플레이 테스트로 확인한다.
3. 2단계 기본 수요가 증가하므로 리모델링 직후 대기와 불만이 늘 수 있다. 인지도 수치 보존과 수요 공식 변경을 화면에서 설명하고, 필요하면 신규 상권 수요를 점진적으로 적용하는 후속안을 검토한다.
4. 숙련 딜러의 속도 이득과 추가 급여, 대회 전문 딜러의 시간 절감과 일반 영업 복귀 효과를 통합 경제로 비교해야 한다.
5. 18개 전체 성장, 여러 서비스 직원, 시설 개선의 투자 회수율은 아직 검증하지 않았다.
6. 자금 부족 복구 규칙은 별도 테스트가 필요하다. 기본 영업 한 경로가 흑자였다는 사실은 모든 잘못된 투자가 회복 가능하다는 증거가 아니다.

## 4. 구현 전에 채택 여부를 기록할 신규 제안

기존에 확정된 기획을 다시 묻기 위한 목록이 아니다. 이번 문서에서 새로 채운 동작을 식별하는 목록이다.

| 신규 제안 | 초안의 기본안 | 영향 |
|---|---|---|
| 딜러 효율 해석 | 담당 테이블 세션 시간 단축 | 손님 회전과 수익 계산 |
| 초반 수요 투자 | 지역 홍보 구매 | 첫 대회 이전 병목 해결 |
| 데일리 기준 | 게임 내 하루당 대회 예약 1회 | 성장 속도와 플레이 일정 |
| 특별 직원 검증 획득 | 특정 이정표에서 1명씩 확정 지급 | 가챠 없이 능력 비교 |
| 중규모 대회 **밸런스 수치** | 4테이블·4딜러, 참가비 240G, 상금 100G, 개최비 1,800G, 모집 `min(32, floor(D×3))` | 단계 보상 크기. *기능 포함 여부는 제안이 아니라 첫 완성본의 확정 범위다 — 05 채택기록 v1 §1-1 참조* |
| 자금 부족 복구 | 일시 지원을 포함한 긴급 축소 운영 | 실패 비용과 복구 가능성 |
| 오프라인 상한 | 현실 4시간 | 방치 보상과 저장·시간 처리 |
| 리모델링 공사 | 기존 세션 정리 후 전환, 별도 공사 대기 없음 | 자산 보존과 연출 |

인지도 50, 대회 2회, 리모델링 15,000G, 가격표, 배율은 밸런스 조정값이다. 위 동작 규칙과 달리 매번 기획 전체를 바꾸지 않고 데이터로 조정할 수 있도록 만든다.

## 5. Claude Code의 구현 순서

### 작업 A — 규칙과 경제 상태

선택한 기술에 맞춰 경제 상태, 설정 데이터, 플레이어 행동, 분 단위 계산, 정산 이벤트를 분리한다. 화면·오디오·애니메이션에 의존하지 않는 엔진을 만든다.

완료 기준: 고정 수요 8명과 20명에서 투자 효과가 달라지고, 세션 정산 중복이 없으며, 시간 분할 결과가 일치한다. 예상치는 상태 복제 후 같은 엔진으로 계산한다.

### 작업 B — 운영 선택과 대회

직원 4유형, 대기·배치 전환, 서비스·시설, 지역 홍보의 채택안, 소규모·중규모 대회, 자금 복구를 구현한다. 기능별로 비용·조건·실패 이유·상태 변화·저장 항목을 명시한다.

완료 기준: 딜러 중복 배치 금지, 대회 자원 점유, 일반 영업 기회비용, 특별 능력 적용 범위, 복구 모드 종료를 확인한다.

### 작업 C — 성장·리모델링·저장

해금, 6→18개 한도, 1층·2층 설치 지점, 리모델링 준비와 단일 전환, 저장 복구, 오프라인 계산을 구현한다.

완료 기준: Progression의 P01~P15 중 경제·상태 항목을 자동 검증한다. 특히 6테이블·3딜러 상태의 리모델링과 준비 중 재접속을 확인한다.

### 작업 D — 최소 운영 화면

현금, 시간당 수요, 이론 처리 능력, 운영 테이블, 대기·이탈, 서비스 품질·만족도, 실제 매출·비용을 연결한다. 투자 비교와 성장 조건을 실제 엔진 결과로 표시한다.

완료 기준: 개발자가 아닌 사람이 현재 병목과 다음 투자의 이유를 설명할 수 있다. 화면의 경고와 실행 조건이 불일치하지 않는다.

### 작업 E — 비주얼 통합과 실제 플레이 테스트

Visual Bible에 따라 자동 배치, 캐릭터 움직임, 층 전환, 테마, 대회 연출, 리모델링 연출을 붙인다. 경제 이벤트를 받아 표현하고, 연출이 경제 결과를 결정하지 않게 한다.

완료 기준: 1→2단계와 7번째 테이블까지 사람이 직접 플레이한다. 저장 후 다시 이어서 진행하고, 다른 층·백그라운드에서도 경제가 유지되는지 확인한다. 발견한 문제에 따라 수치와 안내를 조정한다.

## 6. 개발 지시문

아래 내용은 전체 게임을 한 번에 만들라는 지시가 아니라, 첫 구현 작업의 범위를 고정하기 위한 인계문이다.

> 이 프로젝트는 이전 홀덤펍 타이쿤과 별개의 신규 프로젝트다. 제공한 GDD의 확정 원칙을 우선한다. Economy/Progression 문서의 초안 규칙은 채택한 버전과 미채택 항목을 먼저 기록하고 임의로 바꾸지 않는다. 이번 작업은 화면에 의존하지 않는 경제 상태와 분 단위 계산, 행동 검증, 세션 단일 정산, 투자 전후 예측, 핵심 경제 검증까지다. 밸런스 수치는 설정 데이터로 분리한다. 실제 포커 핸드 엔진, 직원 가챠, 세계 대회, 3단계 이후 매장은 구현하지 않는다. 문서 간 충돌은 위치와 영향을 보고하고 확정 사항을 임의로 덮어쓰지 않는다. 기능을 구현한 뒤 실행 방법, 검증 결과, 아직 구현하지 않은 범위를 보고한다.

기술 스택과 실제 신규 저장소 경로는 Technical Architecture 단계에서 선택한다. 이 문서 패키지에 사용한 계산 도구는 제품용 코드나 기술 스택 선정 근거가 아니다.

> **채택 결과는 `05_채택기록_v1.md`에 기록했다.** 위 §4 표의 각 제안에 대한 채택/보류/후속 판정, 숫자 표현과 재현성 규칙, 이번 구현 범위가 그 문서에 있다. 작업 A의 실제 산출물은 `src/engine`과 `tests`다.
